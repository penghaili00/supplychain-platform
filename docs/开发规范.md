# SupplyChain 开发规范

## 1. 总则

- 所有开发以当前仓库结构和既有实现为准，不得脱离现有分层另起体系
- 所有文本文件统一使用 `UTF-8` 编码
- 严禁引入 `BOM`
- 新增代码、文档、配置命名应保持清晰一致

## 2. 文档与注释规范

### 2.1 中文注释

- 实体类必须补中文注释
- DTO、VO、请求体、响应体建议补中文注释
- 注释内容应描述业务语义，不写无意义废话

### 2.2 API 文档友好

- 面向接口输出的模型，需要具备足够的中文字段说明
- 不允许只保留英文缩写字段含义而不解释

### 2.3 文档同步

- 变更配置体系时，必须同步更新 `README.md` 与相关文档
- 变更登录、安全、风控规则时，必须同步更新 `app-auth.md`

## 3. 日志与异常规范

- 日志信息优先使用中文
- 异常提示优先使用中文
- 日志内容要包含关键上下文，例如用户 ID、IP、请求标识、配置项名称
- 禁止打印明文密码、签名密钥、完整 Token 等敏感数据

## 4. 分层与包结构规范

### 4.1 模块职责

- `supplychain-admin` 和 `supplychain-api` 只负责 HTTP 接口与调用编排
- 业务核心实现放在 `supplychain-service-provider`
- 跨模块服务契约放在 `supplychain-service-api`
- 通用能力沉淀到 `supplychain-common`

### 4.2 Provider 拆包

`supplychain-service-provider` 统一按领域拆包，例如：

- `admin.user`
- `app.user`
- `auth`
- `audit`
- `rbac`

新增功能优先归入已有领域；没有合适归属时，再新增新的领域包。禁止继续使用大而杂的平铺式目录承载新增代码。

### 4.3 控制器职责

- Controller 不直接写复杂业务逻辑
- 参数校验、调用编排可以放在 Controller
- 核心业务规则必须下沉到 `service-provider`

## 5. 用户体系规范

### 5.1 后台用户与 App 用户分离

- 后台用户使用 `sys_user`
- App 用户使用 `app_user`
- 后台角色关系使用 `sys_user_role`
- App 角色关系使用 `app_user_role`

禁止事项：

- 禁止共用一张用户表
- 禁止通过 `userType` 或类似字段做弱区分
- 禁止后台登录复用 App 登录 DTO
- 禁止 App 登录复用后台用户认证逻辑

### 5.2 登录接口分离

- 后台登录使用后台专属命令对象和服务方法
- App 登录使用 App 专属命令对象和服务方法
- 两端的刷新、资料查询也应按端区分

## 6. 安全规范

### 6.1 App 登录

App 登录必须保留以下能力：

- 验签
- 时间戳校验
- nonce 防重放
- 盐值密码哈希
- 账号维度失败次数锁定
- IP 维度失败次数锁定

### 6.2 密码处理

- App 用户密码使用 `PBKDF2WithHmacSHA256`
- 每个用户必须有独立盐值
- 不允许保存明文密码
- 不允许将哈希参数硬编码到调用方

### 6.3 JWT

- `admin`、`api`、`gateway` 必须共享一套 JWT 核心配置
- JWT 秘钥必须通过环境变量和 Nacos 配置管理
- 不允许把真实生产密钥写入仓库

## 7. 配置规范

### 7.1 纯 Nacos 模式

项目当前采用纯 Nacos 配置模式：

- 运行时业务配置只从 Nacos 读取
- 本地 `application.yml` 只保留应用名、Nacos 连接引导和 `optional:nacos:` 导入
- 仓库内 `nacos/*.yml` 只作为发布源

### 7.2 共享配置与模块配置

共享配置：

- `datasource.yml`
- `redis.yml`
- `mybatis-plus.yml`
- `dubbo-provider.yml`
- `dubbo-consumer.yml`
- `jwt.yml`
- `management.yml`

模块配置：

- `supplychain-admin.yml`
- `supplychain-api.yml`
- `supplychain-gateway.yml`
- `supplychain-mq.yml`
- `supplychain-service-provider.yml`
- `supplychain-task.yml`

规范要求：

- 公共能力抽到共享 Data ID
- 模块特有配置保留在对应模块 Data ID
- 禁止在多个模块 Data ID 中复制相同配置块

### 7.3 环境变量

- 环境相关主机、端口、账号、密码、秘钥必须通过环境变量占位
- 不允许把本机真实账号密码直接提交到仓库

## 8. 数据访问规范

- 表结构变更需要同步更新初始化 SQL
- Mapper 命名与实体命名保持一致
- 领域查询语义要明确，不使用含糊方法名
- 对后台用户和 App 用户的查询、角色、权限逻辑必须分别实现

## 9. 接口模型规范

- `Command` 表示请求入参
- `View` 或 `ProfileView` 表示输出模型
- 后台端与 App 端模型应明确区分
- 模型字段命名优先表达真实业务含义

## 10. 编码规范

- 优先保持现有代码风格一致
- 命名清晰直接，避免过度缩写
- 复杂逻辑可以加简短注释说明意图
- 能复用现有组件时，不重复造轮子

## 11. 测试与验证规范

- 修改配置体系后，至少验证模块能正常加载 Nacos Data ID
- 修改认证链路后，至少验证登录、刷新、权限获取主流程
- 修改数据库结构后，至少验证初始化脚本可执行
- 提交前至少执行一次 `mvn -DskipTests package`

## 12. 提交与交付规范

- 不提交运行时缓存目录，例如 `.dubbo`
- 不提交调试日志目录，例如 `.codex-runlogs`
- 不提交 `target/`、IDE 配置等临时文件
- 若本次修改引入新约束，必须补文档

## 13. 推荐检查清单

提交前建议检查：

- 配置是否只从 Nacos 读取
- 用户分表是否被破坏
- 中文注释是否补齐
- 日志文案是否为中文
- 文件是否为 UTF-8 且无 BOM
- 文档是否同步更新
