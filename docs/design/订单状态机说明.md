# B2B 供应链订单履约平台订单状态机说明

## 1. 文档目标

本文档用于定义一期订单主链的状态流转规则，统一订单在下单、审核、锁库、发货、收货、取消等场景下的状态语义。

状态机文档主要解决以下问题：

- 每个状态代表什么业务阶段
- 什么事件可以触发状态变化
- 哪些角色可以发起该事件
- 定时任务和异常场景如何落到状态流转上

## 2. 设计原则

- 一期只覆盖最小履约闭环，不引入过多复杂分支
- 主订单状态、审核状态、履约状态拆开定义，避免一个状态混杂所有语义
- 状态流转必须可审计、可追踪、可重放关键节点
- 所有非正常终态都必须带原因字段或原因备注
- 为后续拆单、售后、结算预留扩展位，但不提前把状态做得过碎

## 3. 一期状态模型

一期建议拆成三组状态字段：

- `order_status`
  表达订单主状态
- `audit_status`
  表达审核结果
- `fulfillment_status`
  表达履约执行进度

其中，接口列表页和主要业务判断优先使用 `order_status`，审核和履约页面再结合另外两个状态辅助展示。

## 4. 主订单状态定义

### 4.1 `DRAFT`

含义：

- 订单草稿态

一期建议：

- 可以预留
- 如果一期不做购物车草稿，可以不真正落库使用

### 4.2 `PENDING_AUDIT`

含义：

- 客户已提交订单，等待后台审核

可进入来源：

- 客户提交订单成功

可流转去向：

- `AUDIT_REJECTED`
- `PENDING_LOCK`
- `CANCELED`

### 4.3 `AUDIT_REJECTED`

含义：

- 审核驳回

说明：

- 属于一期关闭态之一
- 需要保留驳回原因

### 4.4 `PENDING_LOCK`

含义：

- 审核通过，待锁定库存

说明：

- 该状态用于把“审核通过”和“锁库成功”解耦
- 便于后续接 MQ、重试和补偿

### 4.5 `LOCK_FAILED`

含义：

- 锁库失败

说明：

- 需记录失败原因，例如库存不足、仓库不可用
- 一期可以作为人工处理状态

### 4.6 `PENDING_OUTBOUND`

含义：

- 已锁库，待仓库出库

说明：

- 一期下可视为待拣货 / 待出库的聚合状态

### 4.7 `PENDING_SHIPMENT`

含义：

- 已出库，待登记发货

说明：

- 如果系统设计为出库即发货，该状态可以很短暂
- 但建议保留，便于仓库流程拆分

### 4.8 `PENDING_RECEIPT`

含义：

- 已发货，待客户确认收货

### 4.9 `COMPLETED`

含义：

- 客户已确认收货，或系统自动确认收货

说明：

- 一期主链正常终态

### 4.10 `CANCELED`

含义：

- 订单取消

适用场景：

- 客户取消
- 审核前超时取消
- 人工关闭订单

说明：

- 若已锁库，取消前必须先释放库存

## 5. 配套状态定义

### 5.1 审核状态 `audit_status`

- `NONE`
  尚未进入审核流程
- `PENDING`
  待审核
- `APPROVED`
  审核通过
- `REJECTED`
  审核驳回

### 5.2 履约状态 `fulfillment_status`

- `NONE`
  尚未履约
- `LOCKING`
  锁库处理中
- `LOCKED`
  已锁库
- `OUTBOUNDING`
  出库处理中
- `WAIT_SHIPMENT`
  待登记发货
- `SHIPPED`
  已发货
- `RECEIVED`
  已签收 / 已确认收货

## 6. 状态流转主链

一期推荐的正常流转主链如下：

```text
PENDING_AUDIT
  -> PENDING_LOCK
  -> PENDING_OUTBOUND
  -> PENDING_SHIPMENT
  -> PENDING_RECEIPT
  -> COMPLETED
```

异常流转如下：

```text
PENDING_AUDIT -> AUDIT_REJECTED
PENDING_AUDIT -> CANCELED
PENDING_LOCK  -> LOCK_FAILED
PENDING_LOCK  -> CANCELED
PENDING_OUTBOUND -> CANCELED
PENDING_RECEIPT -> COMPLETED
```

## 7. 状态事件说明

### 7.1 创建订单

触发方：

- 采购客户

前置条件：

- 客户状态正常
- 商品可售
- 地址有效
- 数量满足起订量

状态变化：

- `order_status`: `PENDING_AUDIT`
- `audit_status`: `PENDING`
- `fulfillment_status`: `NONE`

### 7.2 审核通过

触发方：

- 销售 / 运营

前置条件：

- 订单当前处于 `PENDING_AUDIT`

状态变化：

- `order_status`: `PENDING_LOCK`
- `audit_status`: `APPROVED`
- `fulfillment_status`: `LOCKING`

### 7.3 审核驳回

触发方：

- 销售 / 运营

前置条件：

- 订单当前处于 `PENDING_AUDIT`

状态变化：

- `order_status`: `AUDIT_REJECTED`
- `audit_status`: `REJECTED`
- `fulfillment_status`: `NONE`

补充要求：

- 必须记录驳回原因

### 7.4 锁库成功

触发方：

- 系统

前置条件：

- 订单当前处于 `PENDING_LOCK`

状态变化：

- `order_status`: `PENDING_OUTBOUND`
- `fulfillment_status`: `LOCKED`

补充要求：

- 写入库存锁定记录
- 写入库存流水
- 写入订单轨迹

### 7.5 锁库失败

触发方：

- 系统

前置条件：

- 订单当前处于 `PENDING_LOCK`

状态变化：

- `order_status`: `LOCK_FAILED`
- `fulfillment_status`: `NONE`

补充要求：

- 必须记录失败原因

### 7.6 生成出库单

触发方：

- 系统 / 仓库

前置条件：

- 订单当前处于 `PENDING_OUTBOUND`

状态变化：

- `fulfillment_status`: `OUTBOUNDING`

说明：

- `order_status` 可以保持 `PENDING_OUTBOUND` 不变
- 出库执行完成后再推进主状态

### 7.7 出库完成

触发方：

- 仓库人员

前置条件：

- 已存在有效出库单

状态变化：

- `order_status`: `PENDING_SHIPMENT`
- `fulfillment_status`: `WAIT_SHIPMENT`

### 7.8 登记发货

触发方：

- 仓库人员

前置条件：

- 订单当前处于 `PENDING_SHIPMENT`
- 已填写物流单号

状态变化：

- `order_status`: `PENDING_RECEIPT`
- `fulfillment_status`: `SHIPPED`

### 7.9 客户确认收货

触发方：

- 采购客户

前置条件：

- 订单当前处于 `PENDING_RECEIPT`

状态变化：

- `order_status`: `COMPLETED`
- `fulfillment_status`: `RECEIVED`

### 7.10 自动确认收货

触发方：

- 定时任务

前置条件：

- 订单当前处于 `PENDING_RECEIPT`
- 距离发货时间超过设定天数

状态变化：

- `order_status`: `COMPLETED`
- `fulfillment_status`: `RECEIVED`

补充要求：

- 订单轨迹中标记为“系统自动确认收货”

### 7.11 订单取消

触发方：

- 客户 / 运营 / 系统任务

前置条件：

- 当前状态允许取消

建议一期允许取消的主状态：

- `PENDING_AUDIT`
- `PENDING_LOCK`
- `LOCK_FAILED`
- `PENDING_OUTBOUND`

状态变化：

- `order_status`: `CANCELED`

补充要求：

- 如果订单已经锁库，取消前必须先释放锁定库存
- 必须记录取消原因和取消人

## 8. 状态流转约束

### 8.1 禁止跳转

一期明确禁止以下直接跳转：

- `PENDING_AUDIT -> PENDING_RECEIPT`
- `PENDING_AUDIT -> COMPLETED`
- `PENDING_LOCK -> COMPLETED`
- `LOCK_FAILED -> COMPLETED`
- `CANCELED -> COMPLETED`
- `AUDIT_REJECTED -> PENDING_OUTBOUND`

### 8.2 终态定义

一期建议以下状态视为终态：

- `COMPLETED`
- `CANCELED`
- `AUDIT_REJECTED`

说明：

- 终态订单不允许再次进入正常履约流转
- 若后续要支持“重新下单”，建议新建订单，而不是回滚原订单

## 9. 角色权限与状态动作映射

- `采购客户`
  可执行创建订单、查看订单、取消订单、确认收货
- `销售 / 运营`
  可执行审核通过、审核驳回、订单备注、人工取消
- `仓库人员`
  可执行出库、登记发货
- `系统任务`
  可执行超时取消、自动确认收货
- `系统服务`
  可执行锁库成功、锁库失败、库存释放等内部状态推进

## 10. 与定时任务的配合

### 10.1 超时取消任务

处理范围：

- 长时间停留在 `PENDING_AUDIT` 的订单

处理动作：

- 写订单轨迹
- 更新为 `CANCELED`

### 10.2 自动确认收货任务

处理范围：

- 长时间停留在 `PENDING_RECEIPT` 的订单

处理动作：

- 写订单轨迹
- 更新为 `COMPLETED`

## 11. 与库存状态的配合

订单状态机需要和库存动作配套执行：

- `PENDING_LOCK -> PENDING_OUTBOUND`
  代表锁库成功，库存从 `available_qty` 转入 `locked_qty`
- `PENDING_LOCK -> LOCK_FAILED`
  不修改库存结果，但记录失败
- `任一已锁库状态 -> CANCELED`
  需要释放库存，`locked_qty` 回到 `available_qty`
- `PENDING_OUTBOUND / PENDING_SHIPMENT -> PENDING_RECEIPT`
  出库完成后，锁定库存转为实际扣减

## 12. 审计与轨迹要求

以下动作必须同时写入 `sc_order_operation_log`：

- 创建订单
- 审核通过
- 审核驳回
- 锁库成功
- 锁库失败
- 生成出库单
- 出库完成
- 发货登记
- 客户确认收货
- 系统自动确认收货
- 订单取消

同时，关键后台操作建议继续写入 `sys_operation_log`，用于接口级审计。

## 13. 后续扩展方向

当项目进入二期或三期后，状态机可进一步扩展：

- 增加 `PART_SHIPPED` 以支持部分发货
- 增加 `BACKORDERED` 以支持缺货回补
- 增加子单状态机以支持多仓拆单
- 增加售后状态机以支持退货退款
- 增加结算状态机以支持对账与回款

一期先保持状态机清晰、能落地、便于编码，比过早追求复杂覆盖更重要。
