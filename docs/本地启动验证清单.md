# SupplyChain 本地启动验证清单

## 适用范围

这份清单用于从零开始在本地 `local` 环境完成以下流程：

1. 拉取并重建基础设施容器
2. 导入 `supplychain_local` 的 Nacos 配置
3. 打包所有服务
4. 启动本地 Java 服务
5. 验证服务健康状态与网关路由

默认前提：

- 使用 WSL / Linux 终端
- 默认环境文件为 `deploy/env/local.env`
- Nacos 本地命名空间真实 `namespaceId` 为 `supplychain_local`

## 一次性前置检查

### 1. 确认本地环境文件存在

命令：

```bash
ls deploy/env/local.env
```

期望结果：

- 输出 `deploy/env/local.env`

如果不存在，先执行：

```bash
cp deploy/env/local.env.example deploy/env/local.env
```

### 2. 确认本地关键配置

命令：

```bash
grep -E '^SUPPLYCHAIN_(MYSQL_HOST|MYSQL_PORT|MYSQL_USERNAME|MYSQL_PASSWORD|MYSQL_DATABASE|ES_URL|ES_USERNAME|ES_PASSWORD|NACOS_ADDR|NACOS_NAMESPACE|NACOS_NAMESPACE_NAME|NACOS_GROUP)=' deploy/env/local.env
```

期望结果示例：

```dotenv
SUPPLYCHAIN_MYSQL_HOST=127.0.0.1
SUPPLYCHAIN_MYSQL_PORT=3306
SUPPLYCHAIN_MYSQL_USERNAME=root
SUPPLYCHAIN_MYSQL_PASSWORD=123456
SUPPLYCHAIN_MYSQL_DATABASE=supplychain
SUPPLYCHAIN_ES_URL=http://127.0.0.1:9200
SUPPLYCHAIN_ES_USERNAME=elastic
SUPPLYCHAIN_ES_PASSWORD=your-es-password
SUPPLYCHAIN_NACOS_ADDR=127.0.0.1:8848
SUPPLYCHAIN_NACOS_NAMESPACE=supplychain_local
SUPPLYCHAIN_NACOS_NAMESPACE_NAME=supplychain_local
SUPPLYCHAIN_NACOS_GROUP=DEFAULT_GROUP
```

### 3. 确认带空格的变量已经加引号

命令：

```bash
grep -nE 'SUPPLYCHAIN_TASK_DEMO_CRON|SUPPLYCHAIN_JAVA_OPTS' deploy/env/local.env
```

期望结果示例：

```dotenv
SUPPLYCHAIN_TASK_DEMO_CRON='0 0/5 * * * ?'
SUPPLYCHAIN_JAVA_OPTS='-Xms256m -Xmx512m'
```

如果没有引号，`source deploy/env/local.env` 时会失败。

## 一键从头重跑 local

如果你希望彻底从头跑，建议按下面顺序执行。

### 第 1 步：停止本地 Java 服务

命令：

```bash
./scripts/linux/stop-all.sh
```

期望结果：

- 如果之前通过脚本启动过，会看到 `Stopped xxx`
- 如果没有，通过脚本启动过的服务不存在，会看到 `No pid file found for xxx`

这都算正常。

### 第 2 步：停止并删除当前 Compose 容器

命令：

```bash
./scripts/linux/compose.sh down
```

期望结果：

- `supplychain-mysql` / `supplychain-redis` / `supplychain-elasticsearch` / `supplychain-nacos` / `supplychain-rabbitmq` 被移除
- `supplychain_default` 网络被移除

说明：

- 这一步不会删除数据卷
- 如果只是普通重启，本步骤足够

### 第 3 步：如果怀疑 MySQL 旧密码或旧数据干扰，连卷一起删除

命令：

```bash
./scripts/linux/compose.sh down -v
```

期望结果：

- 除容器和网络外，相关命名卷也会被删除

适用场景：

- 改了 `SUPPLYCHAIN_MYSQL_PASSWORD` 后仍然无法连接
- 日志出现 `Access denied for user 'root'`
- 希望本地彻底重新初始化

注意：

- 这一步会删除本地 MySQL/Redis/RabbitMQ 的持久化数据

### 第 4 步：拉镜像、启动基础设施并导入 local Nacos

命令：

```bash
./scripts/linux/bootstrap.sh --pull-first
```

期望结果：

- 先看到 `Pulling infrastructure images...`
- 再看到 `Starting infrastructure containers...`
- 然后依次看到：
  - `Waiting for MySQL...`
  - `Waiting for Redis...`
  - `Waiting for Elasticsearch HTTP...`
  - `Waiting for RabbitMQ...`
  - `Waiting for Nacos HTTP...`
- Nacos 就绪后看到：
  - `Nacos login succeeded.`
  - 一串 `Imported xxx.yml`
  - `Nacos import completed for namespace=supplychain_local, group=DEFAULT_GROUP`
  - `Infrastructure is ready.`

成功标志：

```text
Infrastructure is ready.
```

### 第 5 步：打包所有服务

命令：

```bash
./scripts/linux/build.sh
```

期望结果：

- Maven 输出 `BUILD SUCCESS`
- 最后看到每个模块的 jar 路径，例如：
  - `Built supplychain-service-provider: ...`
  - `Built supplychain-admin: ...`
  - `Built supplychain-api: ...`
  - `Built supplychain-gateway: ...`
  - `Built supplychain-task: ...`
  - `Built supplychain-mq: ...`

成功标志：

```text
BUILD SUCCESS
```

### 第 6 步：启动 local 核心服务

命令：

```bash
./scripts/linux/start-all.sh
```

期望结果：

- 按顺序看到：
  - `Started supplychain-service-provider`
  - `Waiting for supplychain-service-provider on port 8090...`
  - `Started supplychain-admin`
  - `Waiting for supplychain-admin on port 8081...`
  - `Started supplychain-api`
  - `Waiting for supplychain-api on port 8082...`
  - `Started supplychain-gateway`
  - `Waiting for supplychain-gateway on port 9000...`
  - `Started supplychain-task`
  - `Waiting for supplychain-task on port 8083...`
- 最后一行：

```text
All requested services are up.
```

## 每一步验证命令

### 验证 1：检查基础设施容器状态

命令：

```bash
./scripts/linux/compose.sh ps
```

期望结果：

- `mysql`
- `redis`
- `elasticsearch`
- `nacos`
- `rabbitmq`

都处于 `running` / `Up` 状态。

### 验证 2：检查 local Nacos 配置是否导入成功

先登录拿 token：

```bash
TOKEN=$(curl -s -X POST "http://127.0.0.1:8848/nacos/v1/auth/users/login" -d "username=nacos&password=nacos" | sed -n 's/.*"accessToken":"\([^"]*\)".*/\1/p')
echo "$TOKEN"
```

期望结果：

- 输出一段 access token，不为空

再查命名空间：

```bash
curl -s "http://127.0.0.1:8848/nacos/v1/console/namespaces?accessToken=$TOKEN"
```

期望结果：

- 返回中包含：

```json
{
  "namespace": "supplychain_local",
  "configCount": 14
}
```

### 验证 3：检查 Elasticsearch 是否可访问

命令：

```bash
source deploy/env/local.env
curl -u elastic:"$SUPPLYCHAIN_ES_PASSWORD" http://127.0.0.1:9200
```

期望结果：

- 返回 Elasticsearch 节点信息 JSON
- 包含 `cluster_name`、`version` 等字段

### 验证 4：检查 5 个核心服务健康状态

命令：

```bash
curl -s http://127.0.0.1:8090/actuator/health
curl -s http://127.0.0.1:8081/actuator/health
curl -s http://127.0.0.1:8082/actuator/health
curl -s http://127.0.0.1:9000/actuator/health
curl -s http://127.0.0.1:8083/actuator/health
```

期望结果：

- 每条都返回：

```json
{"status":"UP"}
```

### 验证 5：检查网关是否可访问

命令：

```bash
curl -i http://127.0.0.1:9000/
```

期望结果：

- 返回 `404 Not Found` 也算正常
- 因为根路径 `/` 没有业务路由，只要不是连接失败，就说明网关已启动

### 验证 6：验证登录路由是否已接通

注意：

- 登录接口是 `POST`
- 不能用 `GET`

错误示例：

```bash
curl -i http://127.0.0.1:9000/admin/auth/login
```

这会导致日志出现：

```text
Request method 'GET' is not supported
```

正确路由定义：

- `POST /admin/auth/login`
- `POST /api/auth/login`

如果只是验证“路由存在”，至少应该使用 `POST` 请求。

### 验证 7：查看最近日志

命令：

```bash
tail -n 30 .runtime/logs/supplychain-service-provider.log
tail -n 30 .runtime/logs/supplychain-admin.log
tail -n 30 .runtime/logs/supplychain-api.log
tail -n 30 .runtime/logs/supplychain-gateway.log
tail -n 30 .runtime/logs/supplychain-task.log
```

期望结果：

- 没有持续刷新的连接失败异常
- 健康检查无报错
- 若手工用 `GET` 调登录接口，日志会出现 `Request method 'GET' is not supported`，这是请求方式不对，不是服务没起来

## dev / prod 导入命令

如果只是把配置导入本地 Nacos 的多个命名空间，可以执行：

```bash
./scripts/linux/import-nacos.sh --env-file deploy/env/dev.env
./scripts/linux/import-nacos.sh --env-file deploy/env/prod.env
```

期望结果：

- `Nacos import completed for namespace=supplychain_dev, group=DEFAULT_GROUP`
- `Nacos import completed for namespace=supplychain_prod, group=DEFAULT_GROUP`

注意：

- `SUPPLYCHAIN_NACOS_NAMESPACE` 必须填写真实 `namespaceId`
- 不能只改 Nacos 页面展示名而不改真实 ID

## 本次实际排查中遇到的典型问题

### 1. `.env` 中带空格的值未加引号

错误示例：

```dotenv
SUPPLYCHAIN_TASK_DEMO_CRON=0 0/5 * * * ?
SUPPLYCHAIN_JAVA_OPTS=-Xms256m -Xmx512m
```

正确写法：

```dotenv
SUPPLYCHAIN_TASK_DEMO_CRON='0 0/5 * * * ?'
SUPPLYCHAIN_JAVA_OPTS='-Xms256m -Xmx512m'
```

### 2. Nacos 命名空间只改了显示名，没有改真实 ID

错误情况：

- 页面看到的是 `supplychain_dev`
- 但真实 `namespaceId` 仍然是 `dev`

正确做法：

- `namespace`
- `namespaceShowName`

两者都要和环境文件约定一致。

### 3. MySQL 改了密码，但旧 volume 仍在

现象：

```text
Access denied for user 'root'
```

原因：

- MySQL 容器第一次初始化后，后续改 `MYSQL_ROOT_PASSWORD` 不会自动修改库中 root 密码

处理办法：

```bash
./scripts/linux/compose.sh down -v
./scripts/linux/bootstrap.sh --pull-first
```
