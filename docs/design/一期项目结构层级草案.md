# B2B 供应链订单履约平台一期项目结构层级草案

## 1. 文档目标

本文档用于定义当前项目在代码层面的推荐层级结构，重点是 `supplychain-service-provider` 和 `supplychain-service-api` 的业务域划分。

目标不是一次性把所有业务代码补完，而是先把后续要扩展的目录骨架整理清楚，让工程树更稳定。

## 2. 当前推荐模块结构

项目根目录建议继续保持：

```text
SupplyChainPlatform
├─ docs
├─ nacos
├─ scripts
├─ sql
├─ supplychain-admin
├─ supplychain-api
├─ supplychain-common
├─ supplychain-gateway
├─ supplychain-mq
├─ supplychain-service
│  ├─ supplychain-service-api
│  └─ supplychain-service-provider
└─ supplychain-task
```

## 3. `service-provider` 推荐层级

`supplychain-service-provider` 建议长期按“业务域”组织，而不是按技术层平铺。

推荐结构：

```text
com.supplychain.service.provider
├─ admin
│  └─ user
├─ app
│  └─ user
├─ audit
├─ auth
├─ customer
├─ product
├─ pricing
├─ warehouse
├─ inventory
├─ order
├─ fulfillment
├─ shipment
├─ rbac
├─ search
└─ demo
```

## 4. `service-api` 推荐层级

`supplychain-service-api` 建议逐步从当前的 `dto / dubbo` 平铺结构，过渡到按业务域组织的契约结构。

推荐结构：

```text
com.supplychain.service.api
├─ admin
│  └─ user
│     ├─ command
│     ├─ query
│     └─ view
├─ app
│  └─ user
│     ├─ command
│     └─ view
├─ auth
│  ├─ command
│  └─ view
├─ audit
│  ├─ command
│  └─ view
├─ customer
│  ├─ command
│  ├─ query
│  └─ view
├─ product
│  ├─ command
│  ├─ query
│  └─ view
├─ pricing
│  ├─ command
│  ├─ query
│  └─ view
├─ warehouse
│  ├─ command
│  ├─ query
│  └─ view
├─ inventory
│  ├─ command
│  ├─ query
│  └─ view
├─ order
│  ├─ command
│  ├─ query
│  └─ view
├─ fulfillment
│  ├─ command
│  ├─ query
│  └─ view
├─ shipment
│  ├─ command
│  ├─ query
│  └─ view
├─ search
│  ├─ query
│  └─ view
└─ demo
   └─ dubbo
```

说明：

- `command`
  写操作入参
- `query`
  查操作入参
- `view`
  出参视图对象

现有的 `dto` 和 `dubbo` 先保留，后续可以逐步迁移，不建议一次性大搬家。

## 5. 业务域内部推荐结构

每个核心业务域建议逐步收敛到这一套层级：

```text
domain
├─ entity
├─ mapper
├─ service
└─ dubbo
```

说明：

- `entity`
  数据库实体
- `mapper`
  MyBatis-Plus Mapper
- `service`
  领域服务
- `dubbo`
  对外提供的 Dubbo 服务实现

`service-api` 则建议收敛到：

```text
domain
├─ command
├─ query
└─ view
```

## 6. 一期优先扩展顺序

建议按以下顺序继续往里填内容：

1. `customer`
2. `product`
3. `pricing`
4. `warehouse`
5. `inventory`
6. `order`
7. `fulfillment`
8. `shipment`

## 7. 当前已做的结构优化

本次已做两件结构优化：

- 删除了 `provider` 根目录下空的旧平铺目录：
  `entity`、`mapper`、`service`、`dubbo`
- 预建了 `provider` 和 `service-api` 两侧的一期核心业务域目录骨架，便于后续直接往里填内容

另外，这次没有继续保留 `package-info.java` 作为占位方式，改成直接预建空目录，工程树会更干净。

## 8. 当前不建议动的地方

以下结构暂时不建议大改：

- `admin.user`
- `app.user`
- `auth`
- `audit`
- `rbac`
- `search`

这些目录目前已经有实际代码，先保持稳定更合适。
