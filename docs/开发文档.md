# SupplyChain 开发文档

## 1. 文档目标

本文档用于帮助开发人员快速理解 SupplyChain 项目的工程结构、配置体系、开发入口和联调方式。内容以当前代码为准，适用于日常功能开发、缺陷修复和新模块接入。

## 2. 工程结构

### 2.1 聚合模块

```text
SupplyChain
├─ supplychain-common
├─ supplychain-service
├─ supplychain-admin
├─ supplychain-api
├─ supplychain-gateway
├─ supplychain-task
├─ supplychain-mq
├─ nacos
├─ docs
└─ sql
```

### 2.2 模块职责

- `supplychain-common`
  - `supplychain-common-core`：公共领域对象、通用响应、上下文对象
  - `supplychain-common-mybatis`：MyBatis-Plus 基础封装
  - `supplychain-common-security`：JWT、认证、会话等安全支撑
  - `supplychain-common-web`：Web 通用组件
- `supplychain-service`
  - `supplychain-service-api`：Dubbo 接口、DTO、VO
  - `supplychain-service-provider`：业务实现、Mapper、实体、Dubbo 服务提供者
- `supplychain-admin`：后台管理端接口
- `supplychain-api`：App 端接口
- `supplychain-gateway`：统一网关与鉴权入口
- `supplychain-task`：定时任务
- `supplychain-mq`：消息队列扩展
- `nacos`：Nacos 配置发布源
- `sql`：数据库初始化脚本

## 3. Provider 包结构

`supplychain-service-provider` 当前按功能域拆包，推荐继续沿用：

- `admin.user`
- `app.user`
- `auth`
- `audit`
- `rbac`
- `demo`

其中：

- `admin.user`：后台用户数据、查询、Dubbo 暴露
- `app.user`：App 用户数据
- `auth`：登录、令牌、验签、密码哈希、风控
- `audit`：操作日志
- `rbac`：角色、菜单、权限

新增业务时，优先按领域继续拆包，不再把类直接堆到平铺的 `service`、`mapper`、`entity` 根目录下。

## 4. 用户体系

### 4.1 后台用户

- 主表：`sys_user`
- 角色关系：`sys_user_role`
- 主要访问端：`supplychain-admin`

### 4.2 App 用户

- 主表：`app_user`
- 角色关系：`app_user_role`
- 主要访问端：`supplychain-api`

### 4.3 重要约束

- 不允许把后台用户和 App 用户混在一张表
- 不允许通过 `userType` 之类字段继续做弱区分
- 后台登录与 App 登录的 DTO、服务方法、认证逻辑必须分开

## 5. 配置体系

### 5.1 运行原则

项目已经切换为纯 Nacos 模式：

- 运行时业务配置只从 Nacos 读取
- 本地 `application.yml` 只负责 Nacos 连接引导和 Data ID 导入
- 仓库里的 `nacos/*.yml` 是配置源文件，修改后需要同步发布到 Nacos

### 5.2 共享 Data ID

- `datasource.yml`
- `redis.yml`
- `mybatis-plus.yml`
- `dubbo-provider.yml`
- `dubbo-consumer.yml`
- `jwt.yml`
- `management.yml`

### 5.3 模块 Data ID

- `supplychain-admin.yml`
- `supplychain-api.yml`
- `supplychain-gateway.yml`
- `supplychain-mq.yml`
- `supplychain-service-provider.yml`
- `supplychain-task.yml`

### 5.4 常用环境变量

- `SUPPLYCHAIN_MYSQL_HOST`
- `SUPPLYCHAIN_MYSQL_PORT`
- `SUPPLYCHAIN_MYSQL_USERNAME`
- `SUPPLYCHAIN_MYSQL_PASSWORD`
- `SUPPLYCHAIN_REDIS_HOST`
- `SUPPLYCHAIN_REDIS_PORT`
- `SUPPLYCHAIN_REDIS_PASSWORD`
- `SUPPLYCHAIN_REDIS_DATABASE`
- `SUPPLYCHAIN_NACOS_ADDR`
- `SUPPLYCHAIN_NACOS_USERNAME`
- `SUPPLYCHAIN_NACOS_PASSWORD`
- `SUPPLYCHAIN_NACOS_NAMESPACE`
- `SUPPLYCHAIN_NACOS_GROUP`
- `SUPPLYCHAIN_JWT_SECRET`
- `SUPPLYCHAIN_APP_SIGN_SECRET`

### 5.5 配置变更流程

1. 修改仓库中的 `nacos/*.yml`
2. 将对应 YAML 发布到目标 Nacos `namespace` 和 `group`
3. 重启相关服务或依赖 Nacos 动态刷新能力验证变更

## 8. 开发一个新功能的推荐流程

### 8.1 如果是后台端功能

1. 在 `supplychain-service-api` 增加 DTO、VO、Dubbo 接口方法
2. 在 `supplychain-service-provider` 对应领域包下实现业务、Mapper、DubboService
3. 在 `supplychain-admin` 增加 Controller 或调用链路
4. 如果涉及菜单、权限、日志，补齐 RBAC 与审计

### 8.2 如果是 App 端功能

1. 明确是否属于 `app.user` 或 `auth` 领域
2. 在 `supplychain-service-api` 中增加 App 端专属 DTO/接口
3. 在 `supplychain-service-provider` 中实现业务
4. 在 `supplychain-api` 暴露 HTTP 接口
5. 如果涉及登录或用户身份，必须考虑验签、密码哈希、Redis 风控

### 8.3 如果涉及配置

1. 判断是共享配置还是模块专属配置
2. 共享配置放到共享 Data ID
3. 模块特有配置放到对应 `supplychain-*.yml`
4. 不在业务代码中硬编码环境相关参数

## 9. 联调关注点

### 9.1 Dubbo

- `admin`、`api`、`task` 通过 Dubbo 调用 `service-provider`
- 若 Dubbo 无可用提供者，先确认 `supplychain-service-provider` 是否已注册到 Nacos

### 9.2 JWT

- `admin`、`api`、`gateway` 需要共享同一套 JWT 秘钥配置
- 修改 `jwt.yml` 后，需要同步验证网关和两端应用

### 9.3 App 登录

重点关注：

- 请求签名是否正确
- 时间戳是否超时
- nonce 是否重复
- 密码哈希参数是否匹配
- 账号和 IP 风控是否触发

详细规则见 [app-auth.md](app端登录验签.md)。

## 10. 常见问题

### 10.1 服务启动提示 Nacos 配置缺失

- 检查共享 Data ID 和模块 Data ID 是否都已导入
- 检查 `namespace`、`group`、`dataId` 是否完全一致

### 10.2 Provider 启动失败

优先检查：

- MySQL 是否启动
- `SUPPLYCHAIN_MYSQL_USERNAME` 和 `SUPPLYCHAIN_MYSQL_PASSWORD` 是否正确
- 数据库是否已初始化

### 10.3 Admin 或 Api 启动但调用失败

优先检查：

- `supplychain-service-provider` 是否启动
- Dubbo 是否已注册到 Nacos
- `dubbo-consumer.yml` 和 `dubbo-provider.yml` 是否已导入
