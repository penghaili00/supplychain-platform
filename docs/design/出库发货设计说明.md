# B2B 供应链订单履约平台出库发货设计说明

## 1. 文档目标

本文档用于定义一期履约主链中的出库、发货、收货确认设计，统一出库单、发货单、物流信息以及相关状态流转规则。

本文档重点解决以下问题：

- 锁库成功后如何进入仓库执行
- 出库单和发货单如何拆分职责
- 仓库人员在一期需要执行哪些动作
- 发货完成后如何衔接订单待收货与自动确认收货

## 2. 设计范围

一期覆盖以下内容：

- 出库单生成
- 出库明细记录
- 发货单生成
- 物流单号登记
- 待收货状态推进
- 客户确认收货
- 自动确认收货任务衔接

一期暂不覆盖：

- 波次拣货
- 拣货任务分配
- 复杂复核流程
- 多包裹发货
- 部分发货
- 逆向物流

## 3. 设计原则

- 出库与发货分开建模，便于职责清晰
- 一期先支持单仓、整单或整明细履约
- 仓库动作必须可追踪、可审计
- 物流信息以“手工登记单号”为主，不依赖第三方物流接口
- 已发货与已收货必须是两个独立业务阶段

## 4. 核心对象定义

### 4.1 出库单 `sc_outbound_order`

用途：

- 表示仓库执行拣货、复核、出库的业务单据

建议承载的信息：

- 对应订单
- 对应仓库
- 出库状态
- 出库时间
- 执行备注

### 4.2 出库单明细 `sc_outbound_item`

用途：

- 表示出库单下每个订单商品明细的计划出库数量与实际出库数量

### 4.3 发货单 `sc_shipment_order`

用途：

- 表示物流发运单据

建议承载的信息：

- 对应订单
- 对应出库单
- 物流公司
- 物流单号
- 发货状态
- 发货时间
- 签收时间

## 5. 一期履约主流程

### 5.1 主流程概览

```text
订单锁库成功
  -> 生成出库单
  -> 仓库执行出库
  -> 生成或更新发货单
  -> 登记物流单号
  -> 订单进入待收货
  -> 客户确认收货 / 系统自动确认收货
  -> 订单完成
```

### 5.2 过程说明

- 锁库成功后，订单从“库存阶段”进入“仓库履约阶段”
- 出库单侧重仓内执行
- 发货单侧重物流发运信息
- 收货确认侧重订单闭环完成

## 6. 出库单设计

### 6.1 生成时机

建议在锁库成功、订单进入 `PENDING_OUTBOUND` 后生成出库单。

理由：

- 仓库履约需要明确的作业单据
- 有利于后续扩展拣货、复核、波次、部分出库

### 6.2 出库单生成规则

一期建议遵循以下规则：

- 一个订单在一期默认生成一张出库单
- 一个出库单默认对应一个仓库
- 一个出库单下包含多条出库明细

如果后续支持拆单，可自然演进为：

- 一个主订单对应多个出库单
- 一个子单对应一个履约仓

### 6.3 出库单状态建议

一期建议使用以下状态：

- `CREATED`
  已生成，待仓库处理
- `PROCESSING`
  仓库处理中
- `DONE`
  已出库完成
- `CANCELED`
  已取消

### 6.4 出库动作建议

一期仓库人员在后台至少支持以下动作：

- 查看待出库单
- 查看出库单明细
- 确认出库
- 录入备注

一期暂不强制拆成“拣货完成”“复核完成”“装箱完成”等细粒度动作。

## 7. 发货单设计

### 7.1 发货单生成时机

一期建议在“出库完成后”生成发货单，或者在同一事务内更新发货单记录。

### 7.2 发货单状态建议

建议使用以下状态：

- `WAIT_SHIPMENT`
  已出库，待登记发货
- `SHIPPED`
  已发货
- `SIGNED`
  已签收
- `CLOSED`
  已关闭

### 7.3 发货登记内容

一期建议最少登记以下信息：

- 物流公司名称
- 物流单号
- 发货时间
- 操作人

### 7.4 发货单与订单关系

一期默认：

- 一个订单对应一张发货单
- 一张发货单对应一个出库单

后续扩展时可演进为：

- 一个订单对应多张发货单
- 一个子单独立发运

## 8. 状态流转设计

### 8.1 订单状态与出库发货联动

建议按以下方式推进：

- 锁库成功后：
  `order_status = PENDING_OUTBOUND`
- 出库完成后：
  `order_status = PENDING_SHIPMENT`
- 发货登记后：
  `order_status = PENDING_RECEIPT`
- 确认收货后：
  `order_status = COMPLETED`

### 8.2 履约状态联动

- 出库单创建：
  `fulfillment_status = LOCKED` 或 `OUTBOUNDING`
- 出库完成：
  `fulfillment_status = WAIT_SHIPMENT`
- 发货登记：
  `fulfillment_status = SHIPPED`
- 收货完成：
  `fulfillment_status = RECEIVED`

## 9. 关键业务动作说明

### 9.1 生成出库单

触发方：

- 系统

前置条件：

- 订单已锁库成功
- 已确定履约仓

处理动作：

- 创建 `sc_outbound_order`
- 创建 `sc_outbound_item`
- 写订单轨迹

### 9.2 仓库确认出库

触发方：

- 仓库人员

前置条件：

- 出库单状态为 `CREATED` 或 `PROCESSING`

处理动作：

- 更新出库单状态为 `DONE`
- 执行库存正式扣减
- 更新订单为 `PENDING_SHIPMENT`
- 写订单轨迹

### 9.3 登记发货

触发方：

- 仓库人员

前置条件：

- 出库单已完成
- 订单处于 `PENDING_SHIPMENT`

处理动作：

- 创建或更新发货单
- 写入物流公司和物流单号
- 更新发货单状态为 `SHIPPED`
- 订单推进为 `PENDING_RECEIPT`
- 写订单轨迹

### 9.4 客户确认收货

触发方：

- 采购客户

前置条件：

- 订单状态为 `PENDING_RECEIPT`

处理动作：

- 更新发货单状态为 `SIGNED`
- 更新订单状态为 `COMPLETED`
- 写订单轨迹

### 9.5 系统自动确认收货

触发方：

- 定时任务

前置条件：

- 发货后超过预设天数
- 订单仍处于 `PENDING_RECEIPT`

处理动作：

- 更新发货单状态为 `SIGNED`
- 更新订单状态为 `COMPLETED`
- 轨迹写入“系统自动确认收货”

## 10. 页面与接口建议

### 10.1 Admin 端

一期建议至少提供：

- 待出库单列表
- 出库单详情
- 出库确认接口
- 待发货列表
- 发货登记接口
- 发货单详情

### 10.2 App 端

一期建议至少提供：

- 我的订单列表
- 订单详情
- 物流信息展示
- 确认收货接口

## 11. 异常场景处理

### 11.1 出库前取消

如果订单在出库前被取消：

- 出库单关闭
- 锁定库存释放
- 订单进入 `CANCELED`

### 11.2 出库后未发货

一期建议：

- 订单停留在 `PENDING_SHIPMENT`
- 可由后台人工跟进
- 后续可接入“超时未发货预警任务”

### 11.3 发货后重复登记

建议：

- 以发货单状态判断是否允许重复发货
- 已发货状态下再次登记应拦截或走修改物流信息能力

### 11.4 收货重复确认

建议：

- 当订单已处于 `COMPLETED` 时，确认收货接口返回幂等成功或提示已收货

## 12. 审计与轨迹要求

以下动作建议同时写入订单轨迹：

- 出库单生成
- 出库确认
- 发货登记
- 客户确认收货
- 系统自动确认收货
- 出库取消或关闭

以下后台动作建议写入 `sys_operation_log`：

- 仓库出库确认
- 发货登记
- 物流信息修改

## 13. 服务拆分建议

### 13.1 `OutboundDomainService`

职责：

- 出库单创建
- 出库单状态流转
- 出库明细维护

### 13.2 `ShipmentDomainService`

职责：

- 发货单创建
- 发货登记
- 收货确认

### 13.3 `ReceiptConfirmService`

职责：

- 封装客户确认收货和系统自动确认收货逻辑

### 13.4 `FulfillmentOrchestrator`

职责：

- 串联订单、库存、出库、发货、收货状态推进

## 14. 一期不做但建议预留的方向

- 部分发货
- 多次发运
- 多物流单号
- 物流轨迹同步
- 电子面单
- 逆向退货单
