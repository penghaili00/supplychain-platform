# 一期整体开发清单

## 1. 文档目标

本文档用于把一期开发顺序、当前完成状态和后续预留入口放到一张清单里，方便按阶段推进开发、对齐范围和跟踪进度。

本文档以当前仓库代码和现有设计文档为准，重点回答三个问题：

- 一期应该按什么顺序开发
- 当前哪些基础能力已经完成
- 二期支付、物流等能力应该从哪里接入

## 2. 状态说明

- `已完成`
  当前仓库已经具备可复用骨架，能够作为后续开发起点
- `待完成`
  当前仓库还没有形成业务闭环，仍需继续开发

## 3. 当前基线判断

### 3.1 当前已完成

- 工程聚合结构、模块拆分、Nacos 配置体系已经建立
- `Admin` / `App` 登录、刷新令牌、用户资料查询链路已经可用
- `JWT`、网关鉴权、用户上下文、基础审计能力已经接通
- `Flyway` 已具备初始化表结构和一期业务主表迁移
- 一期客户、商品、价格、仓库、库存、订单、出库、发货等核心表已经落表
- `service-provider` 已按业务域建立 `customer`、`product`、`pricing`、`warehouse`、`inventory`、`order`、`fulfillment`、`shipment` 等包结构

### 3.2 当前待完成

- 客户建档、账号开通、商品、仓库、库存、订单等后台业务接口尚未形成完整可用闭环
- `App` 端除登录外，商品浏览、下单、查单、确认收货还未落地
- 订单审核、锁库、分仓、出库、发货、签收等主流程还未打通
- 超时取消、自动确认收货等业务任务还未落地，当前仍是演示任务
- 搜索、审计查询和演示初始化数据仍需继续补齐

## 4. 一期开发顺序

### 4.1 第一步：基础底座与账号体系

- 当前状态：`已完成`
- 本阶段目标：稳定基础设施、统一用户体系、给后续业务开发提供可复用底座
- 当前已完成：
  - 工程结构、配置中心、Dubbo、网关、JWT、公共组件
  - 后台登录、App 登录、令牌刷新、资料查询
  - `sys_user`、`app_user`、`sys_role`、`sys_menu`、`sys_operation_log` 等基础表
  - 后台用户、角色、菜单权限维护接口已补齐
  - 一期后台菜单种子和权限编码已补齐
- 本阶段后续补齐：
  - 一期演示初始化数据补齐
- 交付标准：后台和 App 的鉴权链路稳定，用户上下文、权限校验、操作日志可复用

### 4.2 第二步：后台客户建档 + App 账号开通

- 当前状态：`待完成`
- 本阶段目标：先把客户主数据和采购客户账号打通，作为整个主链入口
- 本阶段开发内容：
  - 客户主档新增、编辑、启停用、列表、详情
  - 客户联系人维护
  - 收货地址维护
  - 基于客户开通 `App` 账号、重置密码、启停用、关联角色
  - `customer` 与 `app_user.customer_id` 的开通和查询链路
- 交付标准：后台可以完成客户建档并开通采购账号，采购客户可以登录 App
- 二期预留入口：
  - 客户授信扩展入口继续沿用 `credit_enabled`、`credit_limit`
  - 客户结算能力继续沿用 `settlement_type`

### 4.3 第三步：后台商品、价格、仓库、库存主数据

- 当前状态：`待完成`
- 本阶段目标：准备下单前所需的全部主数据，但只做一期最小可用范围
- 本阶段开发内容：
  - 商品分类、SPU、SKU 管理
  - 商品上下架、SKU 启停用
  - 基础价、客户价、最小起订量维护
  - 仓库管理、仓库优先级维护
  - 库存列表、库存调整、库存流水查询
- 交付标准：后台可以维护客户可售商品、价格和履约仓基础数据
- 二期预留入口：
  - 多仓复杂分仓仍从 `warehouse.priority` 和库存模型继续扩展
  - 价格策略可在二期继续扩展促销价、阶梯价、活动价

### 4.4 第四步：App 商品浏览与下单准备

- 当前状态：`待完成`
- 本阶段目标：让采购客户能在 App 端完成“看商品、看价格、选地址”
- 本阶段开发内容：
  - 商品列表、商品详情
  - 按客户维度返回可见价格和起订量
  - 收货地址查询和默认地址选择
  - 下单确认页金额试算
- 交付标准：采购客户能够基于自身客户身份查看可售商品并进入下单确认
- 二期预留入口：
  - 商品搜索结果可以继续接入 Elasticsearch
  - 商品详情可继续扩展图文、资质、营销信息

### 4.5 第五步：App 下单与订单中心基础

- 当前状态：`待完成`
- 本阶段目标：先把订单创建链路跑通，让订单能稳定落库并可追踪
- 本阶段开发内容：
  - 提交订单
  - 订单主表、明细表落库
  - 订单金额计算
  - 订单轨迹记录
  - 我的订单列表、订单详情
- 交付标准：客户可以提交有效订单，订单状态进入 `待审核`
- 二期预留入口：
  - 主子单结构继续沿用 `parent_order_id`
  - 支付与结算扩展继续沿用 `settlement_status`
  - 售后扩展继续沿用 `after_sale_status`

### 4.6 第六步：后台订单审核与锁库

- 当前状态：`待完成`
- 本阶段目标：把后台运营侧的审核和库存锁定链路打通
- 本阶段开发内容：
  - 待审核订单列表、详情、轨迹
  - 审核通过、驳回、备注、必要改价
  - 库存查询与锁定
  - 锁库失败处理和订单状态流转
- 交付标准：后台可以审核订单并触发锁库，订单进入下一履约状态
- 二期预留入口：
  - 风控拦截、信用校验、额度占用可以挂到审核环节
  - 更复杂的库存占用策略可以继续沿用 `inventory_lock`

### 4.7 第七步：出库发货与物流回填

- 当前状态：`待完成`
- 本阶段目标：打通单仓优先的一期履约链路
- 本阶段开发内容：
  - 基础分仓
  - 出库单生成和出库执行
  - 发货单生成
  - 物流公司、物流单号回填
  - 订单进入 `待收货`
- 交付标准：后台可以完成出库和发货登记，客户可看到发货信息
- 二期预留入口：
  - 当前 `shipment_order` 已预留 `logistics_company`、`logistics_no`、`signed_time`
  - 二期可以新增 `logistics` 领域，对接第三方物流轨迹订阅、回传和签收同步

### 4.8 第八步：确认收货、任务、审计、搜索补齐

- 当前状态：`待完成`
- 本阶段目标：把一期闭环真正收口，并补可观测能力
- 本阶段开发内容：
  - App 主动确认收货
  - 自动确认收货任务
  - 超时取消任务
  - 审计日志查询
  - 订单搜索与异常提示
- 交付标准：可以演示完整的一期履约闭环，关键操作可查、可回溯
- 二期预留入口：
  - 搜索能力可以继续接入 ES 索引同步
  - MQ 可以继续承接订单事件、发货通知、索引刷新

## 6. 二期预留入口

### 6.1 支付入口

- 一期不做在线支付，但订单表已预留 `settlement_status`
- 二期建议新增 `payment` 领域包，独立维护支付单、支付流水、回调记录
- App 端二期可新增“发起支付”“支付结果查询”接口，不影响一期订单主链

### 6.2 物流平台入口

- 一期先做后台手工回填物流单号
- 二期建议新增 `logistics` 领域包，承接三方物流下单、轨迹查询、签收回传
- 当前 `shipment_order` 字段已经可以作为物流集成主挂点

### 6.3 结算与授信入口

- 一期只保留客户结算方式、授信额度和订单结算状态字段
- 二期可继续扩展对账单、账期、回款、开票、额度占用与释放

### 6.4 售后与采购入口

- 一期只预留 `after_sale_status`
- 二期可继续扩展退货退款、缺货回补、采购申请、采购入库、补货策略

## 7. 当前执行建议

当前最合适的推进顺序是：

1. 先做“后台客户建档 + App 账号开通”
2. 再做“后台商品、价格、仓库、库存主数据”
3. 然后立刻接“App 商品浏览 + 下单”
4. 再做“后台审核、锁库、出库、发货”
5. 最后补“确认收货、任务、搜索、审计”

这样可以避免后台流程先写得过重，等 App 接入时再返工订单、价格、地址和状态流转逻辑。
