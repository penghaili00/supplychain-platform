# B2B 供应链订单履约平台设计方案

## 1. 文档目标

本文档用于沉淀 SupplyChain 项目后续演进方向，定义 `B2B 供应链订单履约平台` 的业务边界、核心流程、模块划分与阶段路线。

目标有三个：

- 为后续功能开发提供统一业务骨架，避免边做边散
- 将项目控制在单人可持续推进的范围内，同时保留足够的简历含金量
- 保证每一阶段都能形成独立可演示、可验证、可继续扩展的交付成果

## 2. 项目定位

本项目面向企业采购交易场景，服务对象包括采购客户、平台销售与运营、仓库、财务、采购专员和供应商。

平台核心价值：

- 让采购客户能够规范地下采购单并跟踪订单进度
- 让平台能够完成审核、锁库存、分仓、发货、签收、售后等履约动作
- 让后台能够完成库存管理、对账结算、采购补货和经营分析

项目不追求一开始覆盖所有供应链细节，而是优先打通高价值的订单履约主链，再逐步补齐售后、结算、采购和分析能力。

## 3. 业务主链

平台长期固定围绕以下主链设计：

`客户下单 -> 订单审核 -> 锁库存 -> 分仓分配 -> 拆单发货 -> 签收确认 -> 对账结算 -> 售后处理 -> 采购补货`

各阶段说明：

- `客户下单`：采购客户选择商品、填写收货信息、提交采购订单
- `订单审核`：销售或运营审核客户资质、价格、数量、账期和风险
- `锁库存`：系统根据订单明细冻结可售库存，避免超卖
- `分仓分配`：系统按照库存、区域、仓库优先级决定履约仓
- `拆单发货`：跨仓、缺货、部分到货等场景下拆分为子单履约
- `签收确认`：客户确认收货，订单进入完成态或待售后态
- `对账结算`：财务按账期或账单进行应收对账、回款管理
- `售后处理`：客户发起退货退款，平台处理退货入库与退款对账
- `采购补货`：库存不足时触发采购申请与供应商协同

## 4. 角色定义

### 4.1 采购客户

- 浏览商品与价格
- 提交采购单
- 查询订单、发货、签收状态
- 确认收货
- 申请售后

### 4.2 销售 / 运营

- 审核订单
- 改价与备注
- 维护客户信息
- 维护价格策略
- 跟踪异常订单

### 4.3 仓库人员

- 查看待出库单
- 执行拣货、出库、发货
- 录入物流信息
- 处理退货入库

### 4.4 财务人员

- 查看对账单
- 管理应收与回款
- 维护账期规则
- 处理开票申请预留能力

### 4.5 采购专员

- 查看缺货商品
- 发起采购申请
- 维护供应商协同信息
- 跟进采购入库与异常

### 4.6 平台管理员

- 管理商品、仓库、客户、供应商、角色权限和系统配置
- 维护运营规则与风控规则

## 5. 业务边界

### 5.1 本项目优先覆盖

- B2B 订单履约主链
- 多角色后台协同
- 库存锁定与分仓发货
- 账期与对账基础能力
- 售后退货基础能力
- 采购补货基础能力
- 搜索、消息、定时任务、审计等平台能力

### 5.2 本项目暂不优先覆盖

- 在线支付网关接入
- 复杂促销引擎
- 多币种与跨境结算
- 完整税务系统
- 实时物流地图
- 复杂 BPM 工作流引擎
- 多法人、多组织、多套核算体系

以上内容后续可以预留扩展点，但不进入当前主规划。

## 6. 核心业务模块

平台整体按四层业务能力建设。

### 6.1 基础主数据层

- `客户中心`
  维护采购客户、联系人、收货地址、账期信息、客户状态
- `供应商中心`
  维护供应商、联系人、供货范围、交期与合作状态
- `商品中心`
  维护 SPU、SKU、分类、品牌、规格、上下架状态
- `仓库中心`
  维护仓库、仓库区域、履约优先级、启用状态
- `价格中心`
  维护销售价、客户专属价、阶梯价、区域价、最小起订量
- `权限中心`
  基于现有 RBAC 维护后台角色、菜单、权限点、数据范围

### 6.2 交易订单层

- `购物车与下单`
  采购客户选择商品并提交订单
- `订单中心`
  管理主订单、子订单、订单明细、订单状态和轨迹
- `订单审核`
  审核客户、价格、库存、账期和异常风险
- `订单改价`
  支持后台调整价格、运费、折扣并留存审计记录
- `订单取消与关闭`
  处理超时未支付、客户取消、审核驳回等场景

### 6.3 履约库存层

- `库存中心`
  维护可售库存、锁定库存、在途库存、库存流水
- `分仓中心`
  按仓库库存、配送区域、履约优先级执行仓库分配
- `拆单中心`
  处理多仓发货、缺货拆单、部分履约等场景
- `出库中心`
  生成出库单并记录出库执行
- `发货中心`
  维护发货单、物流单号、发货时间、签收状态
- `收货确认`
  维护客户确认收货和自动确认收货逻辑

### 6.4 经营协同层

- `售后中心`
  管理退货、退款、换货预留、售后审核和退货入库
- `结算中心`
  生成对账单、统计应收、登记回款、限制超账期下单
- `采购中心`
  处理补货申请、采购单、到货入库、缺货订单回补
- `消息通知中心`
  通过 MQ 处理订单、发货、异常、售后等异步通知
- `搜索中心`
  基于 Elasticsearch 提供商品、订单、客户搜索能力
- `统计报表中心`
  提供订单、履约、库存、财务、客户分析报表
- `风控审计中心`
  处理高风险订单、异常客户、关键操作审计

## 7. 核心流程设计

### 7.1 下单流程

1. 客户浏览商品并选择 SKU、数量、收货地址
2. 系统校验商品状态、价格策略、起订量与客户可见范围
3. 客户提交订单，系统生成订单草稿或待审核订单
4. 记录订单创建事件并写入订单轨迹

### 7.2 审核流程

1. 销售或运营审核订单
2. 校验客户状态、信用状态、账期额度、商品价格与库存情况
3. 审核通过后进入待锁库或待分仓状态
4. 审核拒绝则订单关闭并记录原因

### 7.3 锁库存与分仓流程

1. 根据订单明细查询各仓可售库存
2. 按分仓规则选择履约仓
3. 执行库存锁定
4. 若单仓无法满足，则拆单为多个子订单或进入缺货处理

### 7.4 出库发货流程

1. 生成出库单
2. 仓库执行拣货、复核、出库
3. 系统生成发货单并记录物流单号
4. 更新子订单和主订单状态
5. 发送发货通知事件

### 7.5 签收确认流程

1. 客户查看物流状态
2. 客户主动确认收货，或由系统到期自动确认
3. 订单进入已完成状态
4. 后续进入对账或售后阶段

### 7.6 售后流程

1. 客户提交退货退款申请
2. 平台审核售后原因与商品状态
3. 仓库执行退货入库
4. 财务处理退款或差额结算
5. 更新售后单与原订单状态

### 7.7 采购补货流程

1. 系统识别库存不足或安全库存预警
2. 采购专员发起采购申请
3. 生成采购单并维护供应商交期
4. 到货后执行采购入库
5. 回补缺货订单或补充可售库存

## 8. 一期范围定义

一期目标是打通一个最小但完整的订单履约闭环，让系统能够真实完成一笔采购订单的全链路流转。

### 8.1 一期必须完成

- 客户管理
- 商品与 SKU 管理
- 价格策略基础能力
- 客户下单
- 订单审核
- 库存锁定
- 基础分仓
- 出库发货
- 确认收货
- 订单搜索
- 操作日志
- 超时取消与自动确认收货

### 8.2 一期建议保留预留点

- 子单模型
- 缺货状态
- 售后状态字段
- 对账状态字段
- 采购回补状态字段

### 8.3 一期暂不实现

- 完整退货退款闭环
- 完整对账结算闭环
- 完整采购协同闭环
- 高级分析报表
- 复杂风控规则引擎

## 9. 分阶段迭代路线

### 9.1 第一阶段：交易与基础履约

目标：完成订单从创建到签收的最小闭环。

交付内容：

- 客户、商品、仓库基础主数据
- 订单创建、审核、锁库、发货、签收
- 后台订单查询与轨迹
- 基础 RBAC 与审计

### 9.2 第二阶段：复杂履约增强

目标：让履约逻辑更贴近真实企业场景。

交付内容：

- 多仓分配
- 缺货拆单
- 部分发货
- 超时未发货预警
- MQ 异步通知
- Task 自动任务

### 9.3 第三阶段：售后与结算

目标：补齐订单完成后的经营闭环。

交付内容：

- 售后申请与审核
- 退货入库
- 对账单生成
- 应收与回款登记
- 账期限制

### 9.4 第四阶段：采购协同

目标：让平台具备供应链补货能力。

交付内容：

- 缺货预警
- 采购申请
- 采购单
- 采购入库
- 缺货订单回补

### 9.5 第五阶段：搜索、分析与风控

目标：增强平台效率与亮点能力。

交付内容：

- Elasticsearch 搜索
- 经营分析报表
- 履约效率统计
- 异常订单预警
- 高风险客户识别

## 10. 模块与工程映射

结合当前 SupplyChain 工程结构，建议按如下方式落地：

- `supplychain-api`
  面向采购客户提供下单、查单、确认收货、售后申请等接口
- `supplychain-admin`
  面向后台提供商品、客户、订单、库存、仓库、采购、财务、报表等接口
- `supplychain-service-provider`
  承载订单、库存、履约、售后、采购、结算等核心领域逻辑
- `supplychain-service-api`
  定义 Dubbo 服务契约、DTO、View 和领域命令对象
- `supplychain-task`
  负责超时取消、自动确认收货、库存预警、对账汇总等定时任务
- `supplychain-mq`
  负责订单事件、通知事件、索引同步事件的异步消费
- `supplychain-common`
  复用通用响应、审计、鉴权、MyBatis、上下文等基础能力
- `supplychain-gateway`
  作为统一入口处理路由、JWT 鉴权、限流与链路透传

## 11. 技术能力规划

### 11.1 Redis

用于承载以下能力：

- 热点数据缓存
- 库存锁定辅助数据
- 幂等控制
- 防重复提交
- 下单与接口限流
- 分布式任务锁

### 11.2 RabbitMQ

用于承载以下异步事件：

- 订单创建事件
- 订单审核通过事件
- 发货通知事件
- 售后状态变更事件
- 搜索索引同步事件

### 11.3 Elasticsearch

用于承载以下检索能力：

- 商品全文搜索
- 订单编号与关键字搜索
- 客户维度订单搜索
- 经营分析辅助检索

### 11.4 定时任务

用于承载以下自动动作：

- 超时未支付取消
- 超时未发货预警
- 自动确认收货
- 每日对账汇总
- 安全库存预警扫描

## 12. 核心设计原则

- 所有新增能力优先围绕订单履约主链，不做无主线扩展
- 所有阶段都要形成可演示成果，不做长期无法验证的大设计
- 主数据、交易、履约、经营分层清晰，不在 Controller 中堆积业务逻辑
- 订单状态、库存状态、售后状态、结算状态分别建模，避免混用一个字段承载全部语义
- 关键动作必须保留审计轨迹，包括审核、改价、锁库、出库、退货、结算等
