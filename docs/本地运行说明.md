# SupplyChain 本地运行说明

## 1. 推荐流程

当前本地开发最省事的方式如下：

1. 先把本地环境模板复制为 `deploy/env/local.env`。

```bash
cp deploy/env/local.env.example deploy/env/local.env
```

2. 如需自定义端口、密码、命名空间或本地地址，直接修改 `deploy/env/local.env`。
3. 启动本地基础设施并导入 Nacos 配置：

```bash
./scripts/linux/bootstrap.sh --pull-first
```

如果你的 Nacos 命名空间展示名和真实 `namespaceId` 不一致，请直接修改 `deploy/env/local.env` 中这两个值：

```bash
SUPPLYCHAIN_NACOS_NAMESPACE=actual-namespace-id
SUPPLYCHAIN_NACOS_NAMESPACE_NAME=display-name
```

4. 打包项目：

```bash
./scripts/linux/build.sh
```

5. 启动整套服务：

```bash
./scripts/linux/start-all.sh
```

如需单独排障，也可以：

```bash
./scripts/linux/run-service.sh --service supplychain-service-provider --foreground
```

## 2. 本地环境准备方式

目前支持两种本地依赖准备方式：

- 使用 Docker Compose，这是默认推荐方式。
- 如果你本机已经有现成环境，也可以手动启动 MySQL、Redis、Elasticsearch、Nacos 和 RabbitMQ。

如果你使用 Docker Compose，项目根目录下的 `docker-compose.yml` 会启动：

- MySQL 8
- Redis 7
- Elasticsearch 8
- Nacos 2.3
- RabbitMQ 3.13，并带管理控制台

## 3. Flyway 迁移说明

- `supplychain-service-provider` 负责数据库结构迁移。
- 第一个迁移脚本是 `V1__init_schema.sql`。
- 对于全新的数据库，Flyway 会在 provider 启动时自动创建表结构并写入种子数据。
- 对于已经通过 `sql/supplychain_mysql.sql` 手工初始化过的数据库，Flyway 会通过 `baseline-on-migrate=true` 兼容已有库，避免重复执行 `V1`。

所以，新的本地环境通常不再需要手工导入 `sql/supplychain_mysql.sql`，除非你是在做手工修复或特殊恢复。

## 4. 环境变量

项目运行时仍然通过环境变量读取连接信息。
本地默认环境文件已经统一为 `deploy/env/local.env`，不再使用根目录 `.env` / `.env.example`。

常用变量如下：

```dotenv
SUPPLYCHAIN_MYSQL_HOST=127.0.0.1
SUPPLYCHAIN_MYSQL_PORT=3306
SUPPLYCHAIN_MYSQL_USERNAME=root
SUPPLYCHAIN_MYSQL_PASSWORD=123456

SUPPLYCHAIN_REDIS_HOST=127.0.0.1
SUPPLYCHAIN_REDIS_PORT=6379
SUPPLYCHAIN_REDIS_PASSWORD=
SUPPLYCHAIN_REDIS_DATABASE=0

SUPPLYCHAIN_ES_URL=http://127.0.0.1:9200
SUPPLYCHAIN_ES_USERNAME=elastic
SUPPLYCHAIN_ES_PASSWORD=

SUPPLYCHAIN_NACOS_ADDR=127.0.0.1:8848
SUPPLYCHAIN_NACOS_USERNAME=nacos
SUPPLYCHAIN_NACOS_PASSWORD=nacos
SUPPLYCHAIN_NACOS_NAMESPACE=supplychain_local
SUPPLYCHAIN_NACOS_NAMESPACE_NAME=supplychain_local
SUPPLYCHAIN_NACOS_GROUP=DEFAULT_GROUP

SUPPLYCHAIN_JWT_SECRET=SupplyChain-Change-Me-In-Local-Env-2026
SUPPLYCHAIN_APP_SIGN_SECRET=SupplyChain-App-Sign-Secret-Please-Change-Now-2026
```

说明：

- 各模块的 `application.yml` 现在只保留启动引导和 Nacos 导入相关配置。
- 运行期的共享配置仍然来自 `nacos/` 目录下这些 YAML 文件。
- `bootstrap.sh` 会把 `nacos/*.yml` 全部导入到目标命名空间和分组中。
- `bootstrap.sh` 和 `import-nacos.sh` 都同时兼容“开启鉴权的 Nacos”和“允许匿名访问的 Nacos”。

## 5. 全量构建与验证

在项目根目录执行完整验证：

```bash
./scripts/linux/build.sh --with-tests
```

这条命令现在会一次完成三件事：

- 运行单元测试
- 生成 JaCoCo 覆盖率报告
- 对齐 GitHub Actions CI 的执行方式

## 6. 单独刷新 Nacos 配置

如果你只改了 `nacos/` 目录下的配置文件，想单独刷新 Nacos，可以执行：

```bash
./scripts/linux/import-nacos.sh
```

## 7. 启动顺序

1. MySQL
2. Redis
3. Elasticsearch
4. Nacos
5. 如果要用 `supplychain-mq`，再启动 RabbitMQ
6. `supplychain-service-provider`
7. `supplychain-admin`
8. `supplychain-api`
9. `supplychain-gateway`
10. `supplychain-task`
11. `supplychain-mq`

## 8. 已知本地运行约束

- 如果 Nacos 没启动，各模块在注册服务或导入配置时可能失败。
- 如果 MySQL 没启动，`supplychain-service-provider` 无法执行 Flyway 迁移，也无法初始化持久层。
- 如果 Redis 没启动，Token 会话和单点登录能力无法正常工作。
- 如果 Elasticsearch 没启动，依赖搜索能力的接口会报连接失败或业务异常。
- 如果 RabbitMQ 没启动，在不开发 MQ 模块时请保持 `supplychain.rabbitmq.enabled=false`。
