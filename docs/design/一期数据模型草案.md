# B2B 供应链订单履约平台一期数据模型草案

## 1. 文档目标

本文档用于定义一期主链建设所需的核心数据对象，为后续数据库建表、实体设计、Mapper 编写和接口建模提供统一基线。

本文档关注三件事：

- 一期到底需要哪些核心表
- 各表在业务上承担什么职责
- 表与表之间的关系和扩展边界如何设计

本文档当前是草案，字段级 SQL 可在后续建表阶段继续细化，但命名和边界应尽量先稳定。

## 2. 建模原则

- 优先围绕 `下单 -> 审核 -> 锁库 -> 发货 -> 收货` 主链建模
- 主数据、交易、库存、履约、审计分层建模，不混在一张大表里
- 订单状态、库存状态、履约状态分别表达，不用一个字段承载全部语义
- 表结构预留售后、结算、采购扩展位，但一期不做完整实现
- 关键业务流水必须可追踪，不能只保留最终结果
- 尽量与当前工程已有基础表命名风格保持一致，采用下划线表名

## 3. 一期数据域划分

一期建议按以下数据域建设：

- `基础身份域`
  承载后台用户、App 用户、角色、菜单、操作日志
- `客户域`
  承载采购客户主数据、联系人、地址、客户状态
- `商品域`
  承载分类、SPU、SKU、价格策略
- `仓库库存域`
  承载仓库、库存、库存流水、锁库记录
- `订单履约域`
  承载订单主表、订单明细、订单轨迹、出库单、发货单

## 4. 与现有基线表的关系

当前项目 SQL 中已经存在以下基础表：

- `sys_user`
- `app_user`
- `sys_role`
- `sys_menu`
- `sys_user_role`
- `app_user_role`
- `sys_role_menu`
- `sys_operation_log`

这些表继续作为平台基础设施表保留，一期新增业务表建议在此基础上扩展，不要推翻已有登录、RBAC、审计骨架。

其中 `app_user` 在一期直接增加 `customer_id` 字段，用于建立“登录账号 -> 客户主体”的直接归属关系。

建议关系为：

- 一个 `sc_customer` 可以对应多个 `app_user`
- 一个 `app_user` 在一期只归属一个 `sc_customer`

这样做的好处是：

- 一期实现简单
- 登录后可以快速拿到客户上下文
- 下单、查单、地址、价格查询都更容易按客户隔离

## 5. 一期核心业务表清单

### 5.1 客户域

#### `sc_customer`

用途：

- 表示 B2B 采购客户主档
- 区分客户状态、客户等级、结算方式和授信预留能力

建议核心字段：

- `id`
- `customer_code`
- `customer_name`
- `customer_type`
- `customer_level`
- `sales_owner_id`
- `status`
- `credit_enabled`
- `credit_limit`
- `settlement_type`
- `remark`
- `created_by`
- `created_time`
- `updated_by`
- `updated_time`
- `deleted`

说明：

- `credit_limit` 一期可以只做预留，不强制实现完整额度控制
- `sales_owner_id` 用于后续客户归属和数据权限扩展

#### `sc_customer_contact`

用途：

- 存储客户联系人

建议核心字段：

- `id`
- `customer_id`
- `contact_name`
- `mobile`
- `phone`
- `email`
- `is_default`
- `status`

#### `sc_customer_address`

用途：

- 存储客户收货地址

建议核心字段：

- `id`
- `customer_id`
- `receiver_name`
- `receiver_phone`

- `is_default`
- `status`

## 6. 表关系草案

一期建议采用以下核心关系：

- `sc_customer` 1 对多 `sc_customer_contact`
- `sc_customer` 1 对多 `sc_customer_address`
- `sc_product_category` 1 对多 `sc_product_spu`
- `sc_product_spu` 1 对多 `sc_product_sku`
- `sc_customer` + `sc_product_sku` 1 对多 `sc_price_policy`
- `sc_warehouse` + `sc_product_sku` 1 对多 `sc_inventory`
- `sc_order_main` 1 对多 `sc_order_item`
- `sc_order_main` 1 对多 `sc_order_operation_log`
- `sc_order_item` 1 对多 `sc_inventory_lock`
- `sc_order_main` 1 对多 `sc_outbound_order`
- `sc_outbound_order` 1 对多 `sc_outbound_item`
- `sc_order_main` 1 对多 `sc_shipment_order`

## 8. 索引建议

一期建议重点关注以下索引：

- `sc_customer.customer_code` 唯一索引
- `sc_product_spu.spu_code` 唯一索引
- `sc_product_sku.sku_code` 唯一索引
- `sc_price_policy(customer_id, sku_id, status)` 组合索引
- `sc_inventory(warehouse_id, sku_id)` 唯一索引
- `sc_order_main.order_no` 唯一索引
- `sc_order_main(customer_id, order_status, created_time)` 组合索引
- `sc_order_item(order_id)` 普通索引
- `sc_inventory_lock(order_id, order_item_id)` 组合索引
- `sc_outbound_order(order_id)` 普通索引
- `sc_shipment_order(order_id)` 普通索引
- `sc_order_operation_log(order_id, operate_time)` 组合索引

## 9. 一期建议统一字段

为了减少重复设计，一期新增业务表建议统一带以下通用字段：

- `created_by`
- `created_time`
- `updated_by`
- `updated_time`
- `deleted`

部分状态流转强相关的表建议补充：

- `status`
- `remark`
- `version`
