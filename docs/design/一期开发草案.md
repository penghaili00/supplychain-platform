# B2B 供应链订单履约平台一期开发草案

## 1. 文档目标

本文档用于承接《B2B 供应链订单履约平台设计方案》，将一期建设范围进一步落到可执行的开发层面。

一期的目标不是把所有供应链能力一次性做完，而是交付一个能够真实演示、可持续迭代、具备业务主链闭环的最小版本。

本文档重点解决四个问题：

- 一期到底做哪些业务能力
- 一期各模块如何映射到当前工程
- 一期推荐按什么顺序开发
- 一期上线或演示时如何判断“已经完成”

## 2. 一期建设目标

一期围绕 `客户下单 -> 订单审核 -> 锁库存 -> 分仓发货 -> 确认收货` 主链建设，交付一个可演示的 B2B 订单履约闭环。

一期完成后，系统应具备以下结果：

- 采购客户可以完成登录、浏览商品、提交采购订单、查询订单、确认收货
- 后台可以完成客户、商品、仓库、库存、订单审核、发货、订单查询等核心操作
- 服务层可以完成订单创建、库存锁定、基础分仓、出库发货、订单轨迹记录
- 定时任务可以处理超时取消、自动确认收货
- 系统具备基础审计日志、基础搜索和后续扩展字段预留

## 3. 一期业务范围

### 3.1 一期必做范围

- 客户基础资料管理
- 商品分类、SPU、SKU 基础管理
- 客户价格基础能力
- 客户下单
- 订单审核
- 库存查询与锁定
- 单仓优先的基础分仓
- 出库单与发货单生成
- 物流单号回填
- 客户确认收货
- 订单搜索与订单轨迹
- 关键操作审计日志
- 超时取消任务
- 自动确认收货任务

### 3.2 一期明确不做

- 在线支付
- 完整账期结算闭环
- 完整退货退款闭环
- 采购申请与采购入库闭环
- 多仓复杂拆单算法
- 风控规则引擎
- BI 大屏与复杂统计分析

### 3.3 一期预留扩展点

- 主订单 / 子订单模型
- 缺货状态与回补状态
- 售后状态字段
- 结算状态字段
- 采购回补状态字段
- MQ 事件表或事件对象扩展位

## 4. 一期角色与使用场景

### 4.1 采购客户

- 登录 App 端
- 浏览可见商品与价格
- 提交采购订单
- 查看订单状态和发货信息
- 确认收货

### 4.2 销售 / 运营

- 查看订单待审核列表
- 审核订单
- 调整价格或备注
- 查询订单轨迹

### 4.3 仓库人员

- 查看待出库单
- 执行出库
- 录入物流单号
- 推动订单进入已发货状态

### 4.4 平台管理员

- 管理客户、商品、仓库、库存、角色权限
- 查看审计日志

## 5. 一期核心流程

### 5.1 下单流程

1. 采购客户登录 App 端。
2. 客户浏览商品和 SKU，并根据客户价选择采购数量。
3. 系统校验商品状态、起订量、价格可见性和客户状态。
4. 创建订单和订单明细，状态进入 `待审核`。
5. 写入订单轨迹和订单创建审计记录。

### 5.2 审核与锁库流程

1. 后台运营查看待审核订单。
2. 审核时校验客户状态、价格、库存和收货信息。
3. 审核通过后触发库存锁定。
4. 锁库成功后订单进入 `待出库` 或 `待发货`。
5. 锁库失败则订单进入 `库存不足` 或 `审核失败`。

### 5.3 发货流程

1. 系统按基础仓库优先级确定履约仓。
2. 生成出库单。
3. 仓库完成拣货、复核、出库。
4. 录入物流单号，生成发货单。
5. 订单更新为 `待收货`，写入订单轨迹。

### 5.4 收货流程

1. 客户查看物流信息。
2. 客户主动确认收货，或定时任务自动确认。
3. 订单进入 `已完成`。
4. 保留售后、结算扩展状态位。

## 6. 一期模块拆分

### 6.1 基础主数据模块

- `客户中心`
  维护客户主数据、联系人、地址、状态、客户等级
- `商品中心`
  维护分类、SPU、SKU、上下架、基础属性
- `价格中心`
  维护商品销售价、客户专属价、最小起订量
- `仓库中心`
  维护仓库、仓库优先级、仓库状态
- `库存中心`
  维护可售库存、锁定库存、库存流水

### 6.2 交易与履约模块

- `订单中心`
  维护订单主表、订单明细、订单状态、订单轨迹
- `订单审核`
  承接人工审核、改价、审核通过与驳回
- `分仓与锁库`
  处理仓库选择、库存锁定和锁定失败
- `出库发货`
  处理出库单、发货单、物流单号和发货状态
- `签收确认`
  处理主动确认收货和自动确认收货

### 6.3 平台能力模块

- `RBAC`
  维护后台角色、菜单和权限点
- `审计日志`
  记录审核、改价、出库、发货、确认收货等关键动作
- `定时任务`
  处理超时取消和自动确认收货
- `搜索能力`
  一期先保证订单列表检索可用，ES 能力以接口预留为主

## 7. 一期工程落地建议

### 7.1 模块职责映射

- `supplychain-api`
  提供客户登录、商品浏览、提交订单、我的订单、确认收货接口
- `supplychain-admin`
  提供客户、商品、仓库、库存、订单审核、出库发货、订单查询接口
- `supplychain-service-api`
  定义订单、库存、商品、客户、履约相关 Dubbo 契约和 DTO
- `supplychain-service-provider`
  实现一期核心领域逻辑
- `supplychain-task`
  实现超时取消、自动确认收货任务
- `supplychain-mq`
  一期以事件对象预留为主，可先不做复杂消费链路
- `supplychain-common`
  复用响应、鉴权、审计、MyBatis 基础能力
- `supplychain-gateway`
  统一入口和 JWT 鉴权

### 7.2 service-provider 推荐领域拆包

建议在 `supplychain-service-provider` 内按业务域逐步增加以下包：

- `customer`
- `product`
- `pricing`
- `warehouse`
- `inventory`
- `order`
- `fulfillment`
- `shipment`
- `audit`

其中：

- `order` 负责订单创建、审核、状态流转、轨迹
- `inventory` 负责库存查询、锁定、释放、流水
- `fulfillment` 负责分仓、出库、发货编排
- `shipment` 负责物流单号和收货确认

## 8. 一期核心数据对象草案

一期建议优先稳定以下核心对象，字段细化可在数据模型文档中继续展开：

- `customer`
  客户基础信息、客户状态、客户等级、结算方式预留
- `customer_address`
  收货地址、联系人、电话、区域编码
- `product_spu`
  商品主档、分类、品牌、上下架状态
- `product_sku`
  SKU 编码、规格、销售单位、商品状态
- `price_policy`
  客户价、基础价、起订量、生效状态
- `warehouse`
  仓库名称、区域、优先级、启用状态
- `inventory`
  SKU 维度库存、可售库存、锁定库存
- `inventory_log`
  锁定、释放、扣减、回补流水
- `order_main`
  主订单、客户、金额、状态、履约状态、结算状态预留
- `order_item`
  订单商品明细、数量、单价、小计
- `order_operation_log`
  订单轨迹、操作人、操作类型、备注
- `outbound_order`
  出库单、仓库、状态、执行时间
- `shipment_order`
  发货单、物流公司、物流单号、发货时间、签收状态

## 10. 推荐开发顺序

为了保证开发过程逻辑紧密、环环相扣，一期建议严格按以下顺序推进：

### 10.1 第一步：稳定基础底座

- RBAC 基础可用
- App / Admin 鉴权链路可用
- 客户、商品、仓库基础表和基础接口可用

### 10.2 第二步：完成订单创建链路

- 商品展示
- 客户下单
- 订单主表和明细表落库
- 订单轨迹记录

### 10.3 第三步：完成审核与锁库链路

- 后台审核订单
- 库存查询与锁定
- 锁库失败处理
- 状态机第一版落地

### 10.4 第四步：完成出库发货链路

- 基础分仓
- 出库单生成
- 发货登记
- 订单进入待收货

### 10.5 第五步：完成签收与任务链路

- 客户确认收货
- 自动确认收货任务
- 超时取消任务

### 10.6 第六步：补足管理与可观测能力

- 订单搜索
- 审计日志
- 基础异常提示
- 文档和接口说明补齐

## 12. 一期验收标准

满足以下条件，可以认为一期主链开发完成：

- 客户可以在 App 端提交有效订单
- 后台可以审核订单并触发库存锁定
- 系统可以为订单分配基础履约仓并生成出库单
- 仓库可以登记发货并回填物流单号
- 客户可以确认收货，订单可进入完成态
- 超时取消和自动确认收货任务可运行
- 关键操作都有审计记录
- 文档、SQL、接口、基础演示数据可供本地复现
